## Conventions

**Threading.** Pt is single-threaded. Every function, callback, timer and frame must be driven from the thread that created the application. Do not call the C API from worker threads; marshal work with a timer or an application-owned queue instead.

**Ownership.** Constructors that take a parent append to it and transfer ownership to the parent's subtree. Functions returning handles either return a borrowed pointer owned by a container or allocate an object the caller must destroy; each function entry states which applies. Never free a borrowed pointer. `pt_free` releases buffers that Pt explicitly hands to the caller.

**Callback threading and lifetimes.** Callbacks are invoked synchronously on the UI thread during event dispatch, painting or frame advancement. They may call the API, but must not block. A registered callback and its `user_data` stay valid until the callback is replaced or the owning object is destroyed.

**Error behavior.** Functions that can fail by creation or lookup return NULL, false, zero or a documented enum default. `pt_get_last_error` returns a thread-local message for the most recent failure. Setters are no-ops for NULL objects, mismatched widget kinds and out-of-range indices; they do not report errors through return values. Text is UTF-8; text offsets are byte positions.

**Valid widget kinds.** Functions with a kind-specific prefix operate on the named widget kind and ignore other kinds. Functions prefixed `pt_widget_` work with any widget unless their description narrows the set.

## app.h

Application lifecycle, timers and preference.

**Contract**

Threading. UI thread only, including getters. Timers and the accessibility
event callback run on that thread.
Ownership. pt_app_create returns an application owned by the caller until
pt_app_destroy, which destroys its windows, widget trees, overlays and
timers. Timer ids are values, not handles; a fired id is forfeited.
Errors. pt_app_create returns NULL and sets pt_get_last_error when the
compositor connection fails. pt_app_run and pt_app_run_for return -1 only on
a connection failure; timeout and a normal quit return 0.
pt_app_add_timeout returns 0 when the timer could not be queued.
pt_app_set_font_family copies the string. Theme setters clamp as documented
in theme.h; queries return the stored value. pt_app_set_font_fallbacks and
its per-family variant copy the families and are described beside the
declarations.
Callbacks. A timer callback is one-shot, runs on the UI thread and may not
block; user_data must stay valid until it fires or the timer is cancelled.

### pt_app_set_ui_direction

```c

```

**Header:** [`pt/app.h`](../include/pt/app.h)

fallback in the resolution chain widget -> nearest explicit ancestor ->

## base.h

Core types, errors and memory.

**Contract**

Threading. Pt is single-threaded. Every function that reads or mutates an
application, window, widget, overlay, accessibility model, drag or gesture
state must run on the UI thread that owns the application, including getters
and queries. The exceptions are the value helpers declared in this header and
a short list of functions that touch only caller-owned data: pt_rgba, pt_rgb,
pt_color_alpha, pt_ease, pt_ease_value, the pt_transition_* functions,
pt_uri_list_count, pt_uri_list_get, pt_free and pt_get_last_error. Those keep
no shared mutable state; pt_get_last_error is thread-local. Callbacks always
run on the UI thread. There is no locking, so an off-thread call to anything
else is undefined behavior even when it only reads.

Ownership. Constructors that take a parent append the new object to it and
transfer ownership to the parent's subtree. A handle returned by a container
or a lookup is borrowed and stays valid until the owning object is destroyed
or the specific function documents a shorter lifetime. Only buffers that Pt
explicitly hands to the caller are caller-owned and released with pt_free;
every other returned pointer is borrowed and must not be freed. Strings
passed to setters are copied unless the declaration says otherwise.

Errors. One error model applies to the whole API. Creation and lookup
functions return NULL, false, zero or a documented sentinel on failure and
set the thread-local message returned by pt_get_last_error. Setters return
void and are no-ops for NULL objects, a mismatched widget kind or an
out-of-range index; they do not report an error. Functions returning bool
return false for an invalid object or an operation that does not apply.
Getters clamp their arguments and return a default instead of failing.
Allocation failure is fatal: Pt prints a diagnostic and aborts rather than
returning a half-initialized object.

Strings and callbacks. Text is UTF-8 and text offsets are byte positions.
A pointer argument passed to a callback is valid only for the duration of
that callback unless the callback typedef says otherwise; copy the data to
keep it. user_data is passed through unchanged and must stay valid until the
callback is replaced or the owning object is destroyed.

## custom.h

Custom painting, IME, file-descriptor watches and raw input.

**Contract**

Threading. UI thread only, including paint callbacks and getters.
Ownership. The paint context is borrowed for the duration of the callback and
becomes invalid when it returns. Strings passed to drawing helpers are read
only for the duration of the call; they are not retained.
Errors. Drawing helpers are no-ops for NULL contexts, empty rectangles and
transparent colors. Font lookup failure is silent and draws nothing.
Callbacks. A paint callback runs during the window paint pass. It must not
call setters that change layout or destroy widgets, because the paint pass is
traversing the tree; use pt_app_add_timeout(..., 0, ...) to defer such work.
All coordinates are logical pixels relative to the widget's top-left corner,
and text sizes are logical pixels. Pt applies the window scale internally.

non-positive size. Since 1.1.

## dnd.h

External drag and drop.

**Contract**

Threading. UI thread only. Drop, offer and stream callbacks run on the UI
thread from the event loop.
Ownership. pt_drop_offer_mime, pt_drop_offer_selected_mime and
pt_drop_stream_mime return borrowed strings that stay valid for the callback
that inspected them, or until the stream ends. pt_drop_offer_read returns a
Pt-owned stream that must not be freed; it stays valid until its terminal
callback returns. pt_uri_list_get returns caller-owned memory released with
pt_free. Drag data, images and drop-target descriptions are copied; the
caller keeps ownership of the input.
Errors. pt_window_begin_drag returns false for NULL, count 0, a payload set
with no usable entry, no implicit grab, or a compositor rejection.
pt_drop_offer_read returns NULL for a finished offer, an unknown MIME type or
no read backend. A max_bytes overrun ends the stream with
pt_drop_stream_error. Setters are no-ops for NULL.
Lifetimes. An offer is valid during enter_offer and drop_offer only; streams
opened from it outlive the callback. Stream chunks are borrowed for the
duration of the callback and are not NUL-terminated, so concatenate them.
Multiple reads may run concurrently. pt_drop_stream_cancel is safe from the
stream's own callback and delivers pt_drop_stream_cancelled before returning.

## icon.h

Public API declared by icon.h.

**Contract**

Threading. Every function in this header runs on the UI thread that owns the
application, including getters and reference counting. There is no locking.

Naming. The public enum pt_icon names Pt's built-in vector glyphs (see
widget.h); the raster image handle is pt_icon_image. Names could not be
shared without breaking the 1.x ABI, so every new raster function carries the
pt_icon_image prefix.

Ownership and lifetime. pt_icon_image is reference counted. A load or lookup
returns one reference owned by the caller. pt_icon_image_ref returns the same
pointer with one more reference and pt_icon_image_destroy drops one
reference; the last drop frees the decoded pixels and every cached
rasterisation. pt_button_set_icon_image and pt_window_set_icon take their own
reference, so the caller may drop its reference immediately after setting;
passing NULL clears the slot. Getter results are borrowed and become invalid
when the owning widget/window is destroyed, the slot is replaced or the
caller drops its own reference (whichever comes first).

Errors. Loads and lookups return NULL and set pt_get_last_error on failure:
missing or unreadable files, corrupt, empty or unsupported PNG/SVG/SVGZ data,
dimensions above PT_ICON_MAX_DIMENSION, SVG documents with no drawable
shape, and theme names that do not resolve. A failed lookup never crashes or
aborts. Setters return void and ignore NULL objects.

Image support. The loader sniffs the payload. A payload whose first two bytes
are the gzip magic 0x1f 0x8b takes the SVGZ path (see below); no other
compressed container is recognised. Every other payload follows the text
sniff: after an optional UTF-8 BOM and ASCII whitespace, a '<' that opens
`<svg` or an `<?xml` declaration selects the SVG path; every other byte
stream stays on the byte-for-byte PNG path.

PNG. 8-bit non-interlaced colour types 0/2/3/4/6, decoded through the same
bounded decoder as clipboard images (16 MiB input cap, 8192x8192 decoder cap)
with an icon-specific PT_ICON_MAX_DIMENSION cap applied before decoding.

SVG. Parsed by the vendored zlib-licensed nanosvg and rasterised at each
requested device size into the same per-size/scale cache. Supported: rect,
circle, ellipse, line, polyline, polygon and path (including arcs), groups,
transforms, fill and stroke paints, stroke width/cap/join/dash, opacity,
fill-rule, linear and radial gradients, defs, inline `style="..."`
declarations and simple `.class` rules from a `<style>` element. Not
supported: text, images, filters, masks, clipPath, use/symbol references,
markers, animation and the full CSS cascade (id, type and descendant
selectors). Unsupported elements are ignored by the parser; their
descendants are still visited, so a `<text>` child shape would draw. A
document with no usable intrinsic size, an empty document or a truncated
document with no complete shape is rejected with an error. SVG source is
capped at the same 16 MiB input limit and intrinsic dimensions at
PT_ICON_MAX_DIMENSION. Rasterisation preserves the intrinsic aspect ratio
and centres the artwork in the requested pixel box (PNG, by contrast, is
resized to the exact box).

SVGZ. A gzip-compressed SVG document is accepted by both loaders and by
hicolor lookup. Compression is detected from the first two bytes (0x1f 0x8b),
never from a file name, and gzip is the only container understood. The
compressed input is subject to the same 16 MiB input cap, and the inflated
document is capped at 16 MiB as well: a stream that would inflate past that
bound is rejected rather than grown (the decompression-bomb guard). The
inflated bytes must pass the same SVG sniff and the same intrinsic-size,
shape and PT_ICON_MAX_DIMENSION rules, so a gzip-wrapped PNG, gzip-wrapped
non-SVG text or any other gzip payload is rejected with an error. Malformed,
truncated and bad-CRC gzip streams return NULL with an error and never crash.
The handle retains the inflated SVG source, bounded by the same 16 MiB cap,
and re-parses it at each requested size exactly as a plain SVG handle does;
the compressed bytes are not retained and there is no separate SVGZ cache or
tuning knob.

Windows. pt_window_set_icon is best effort. When the compositor advertises
xdg_toplevel_icon_v1, Pt rasterises the image to a dedicated, immutable
wl_shm buffer (never a frame buffer), attaches it with the window's scale and
keeps the buffer alive until the icon is replaced or the window is destroyed.
Without the global, in headless mode and under compositors that do not expose
it (niri, Sway, Weston), the call is a silent no-op: no error is recorded and
the image is still retained so a getter and later submission see it. Pt
re-submits on the next window scale change.

Caching. Rasterised per-size/scale results are cached. The cache is global
and bounded by PT_ICON_CACHE_MAX_ENTRIES and PT_ICON_CACHE_MAX_PIXELS across
all live handles, with at most PT_ICON_IMAGE_CACHE_MAX_ENTRIES per handle;
least-recently-used entries are evicted. A cache miss that cannot fit returns
the untinted fallback path (the icon simply does not draw) rather than
growing without bound.

## picker.h

Public API declared by picker.h.

**Contract**

Overview. The 1.2 pickers are editor fields with a popup surface: a
searchable select, a date picker, a number picker (spin box) and a colour
picker. They are built on an entry, the application-owned pt_popup surface
(include/pt/popup.h) and the existing grid/list primitives, so the popup
placement, dismiss and headless fallback rules of pt_popup apply unchanged.
A picker is a combo-box widget at the core (pt_widget_get_kind reports
pt_widget_combobox) because that is the shipped control kind with the
keyboard, pointer, measurement and accessibility hooks the framework
dispatches to. Applications must use only the functions in this header on a
picker; calling the pt_combobox_* item or mode API on it is a no-op.

Relationship to pt_combobox_filterable. A filterable combo box filters its
own option model into an in-window overlay that is rebuilt on every
keystroke and closes when an option is chosen. The searchable select is the
popup-based form: its list lives in a real pt_popup surface (native where the
compositor allows it), it can carry item data, it reports "no matches",
caps the candidate rows, and it can clear the committed value. Neither
replaces the other: the filterable combo box stays the light in-window
chooser, the select is the searchable list with an app-owned popup.

Threading. UI thread only, including getters, setters, open/close and
accessibility queries.

Ownership. A constructor appends the picker to parent and transfers ownership
to the parent's subtree; a NULL parent returns a detached control owned by
the caller (destroy it with pt_widget_destroy). The control owns its entry,
its stepper buttons, its popup and every row/cell it materializes. Text and
handles returned by getters are borrowed and invalidated by the next mutation
of that control. Strings passed to setters and callbacks are copied. Item data
pointers in pt_select are borrowed from the application and must stay valid
while the item exists.

Errors. Setters are no-ops for a NULL or mismatched widget and for invalid
arguments; the text-commit setters return false and record pt_get_last_error.
A rejected text commit leaves the previous value and the previous display
text untouched (the field is restored). Constructors return NULL and set the
error only for allocation failure; a detached picker is legal and opens its
popup once it has a window.

Callbacks. All callbacks run on the UI thread after the control state has
been updated. The widget payload is the picker; callbacks may read it, may
open or close a popup, and may destroy the picker. When a callback destroys
the picker, the picker does not touch it afterwards; the popup is closed or
destroyed as part of that destruction. Do not assume the picker is attached
after the callback returns.

Focus. The focusable target is the entry inside the control, matching the
filterable combo box. While a popup is open the entry keeps focus, so typing
still filters a select or edits a date/number/colour text. Dismissing the
popup (outside click, Escape, Tab, choosing a value) restores focus to the
entry. Tab closes the popup and continues in the normal focus order.

Accessibility. Each control carries an accessible name (a sensible default
per kind; applications override it with pt_widget_set_a11y_name), the combo
box role, except the number picker, which reports the spin button role
because it has no popup. A popup control reports the expanded state while
its popup is open; the number picker reports no expandable state. Every
control exposes a numeric value: select exposes the
selected item index (-1 for none), date exposes YYYYMMDD (0 when empty),
number exposes the value (only while it has one) and colour exposes its RGB
part normalised to [0, 1], because the accessibility Value interface carries
one float and alpha would not survive it. Popup rows and calendar/palette
cells expose names and the selected state; a select row that carries the
committed value also exposes the current state through the built-in check
glyph.

Limits. The select model is capped at PT_SELECT_MAX_ITEMS items and a popup
exposes at most PT_PICKER_MAX_CANDIDATES matching rows. The colour palette is
capped at PT_COLOR_MAX_PRESETS presets. A calendar always renders six weeks
(42 cells) so month navigation cannot grow the tree without bound.

## popup.h

Public API declared by popup.h.

**Contract**

Threading. UI thread only, including getters, show, reposition and dismiss.
Ownership. pt_popup_create takes a parent window and a content widget; the
popup adopts the content widget and its subtree. On pt_popup_destroy the
popup destroys the content tree, so the application must not use or free the
content afterwards. pt_popup_content returns a borrowed pointer that stays
valid until the popup is destroyed. A popup is destroyed automatically when
its parent window is destroyed; the handle is invalid from that moment and
must not be used or destroyed again. Destroying a popup does not invoke the
dismiss callback. The dismiss callback never owns the popup: it may destroy
or re-show it.
Errors. pt_popup_create returns NULL and sets pt_get_last_error for a NULL
window, a NULL/window-root content widget, content that belongs to another
window, or invalid parent state. pt_popup_show and pt_popup_reposition
return false and set the error for a NULL popup, an invalid (non-finite or
negative-size) anchor, a destroyed parent window, or the per-window open
limit. pt_popup_dismiss, pt_popup_destroy and setters are no-ops for NULL.
Callbacks. pt_popup_dismiss_callback runs on the UI thread after the popup
has closed: pt_popup_is_open is already false when it runs. It may destroy
the popup, re-show it with a new anchor, open another popup, or mutate the
widget tree. The callback runs exactly once for each show that ends through
dismissal (outside click, Escape, grab break or pt_popup_dismiss); it does
not run on pt_popup_destroy or parent-window destruction. user_data must
stay valid until the callback is replaced or the popup is destroyed.
Placement. The anchor is a rectangle in parent-window logical pixels.
Native popups use xdg_positioner flip/slide constraints and the compositor's
work area. When the window is not shown/configured or the platform has no
xdg-shell popup support, the popup follows the in-window overlay fallback and
is flipped and slid inside the window content area instead. Menu, tooltip and
combobox native-popup policy (pt_window_set_popup_policy) also applies here.
Accessibility. The popup exposes a panel that contains the content widget,
carries the content's accessible name (or "Popup"), and announces the
showing state while open.

## theme.h

Theme tokens and helper functions.

**Contract**

The color and metric enums are append-only ABI: existing numeric values never
change and new roles get fresh numbers. pt_theme_token_count and
pt_theme_metric_count are bounds, not roles.
Colors are 0xRRGGBBAA; metrics are logical pixels. Negative metrics clamp to
zero, and a radius_pill may be large because it is clamped to the shorter side
of each shape. Out-of-range token or metric indices are ignored by setters;
the getters return 0 for them.
The setters and getters live in app.h and window.h and are UI-thread only. A
window resolves app tokens first and then its own overrides at paint time; no
allocation is transferred by this header.

This header declares types only.

## widget.h

**Contract**

Threading. UI thread only, including getters and accessibility queries.
Ownership. Constructors append the new widget to parent and transfer
ownership to the parent's subtree. A NULL parent returns a detached tree owned
by the caller and released with pt_widget_destroy. Handles returned by
pt_widget_parent, the pt_tree_* lookups, pt_tabs_get_page and
pt_sidebar_get_item are borrowed. Text returned by a getter is borrowed from
the widget and invalidated by the next mutation of that text. List, table and
tree row/cell widgets are materialized and owned by the view: a bind callback
must configure them but never destroy or reparent them.
Errors. Constructors return NULL and set pt_get_last_error. Setters are
no-ops for NULL, a mismatched widget kind or an out-of-range index. Functions
returning bool return false for an invalid object or an operation that does
not apply. Getters clamp and return a default. Selection and checked-state
setters are silent: they never fire on_select, on_change or on_checked,
matching every set_selected in the API.
Callbacks. All callbacks run on the UI thread. user_data must stay valid until
the callback is replaced or the owning widget is destroyed. A text pointer
passed to a callback is valid only for that call unless its typedef says
otherwise. Callbacks may call the API and may destroy their own widget after
returning; they must not block.
Text input. Pt pushes text-input-v3 state when focus enters a text input,
when a keystroke or pointer gesture changes the text or caret, and when a
composition ends: content type, surrounding text, caret rectangle, then
commit. An empty done with no composition in flight is the input method's
acknowledgement and is ignored, because replying to it would ask for another
acknowledgement. The push moments are part of the frozen contract.
Text. Strings are UTF-8 and offsets are byte positions. Selection endpoints
may be given in either order and are clamped. Strings passed to setters and
span arrays are copied.

### pt_widget_set_ui_direction

```c
void pt_widget_set_ui_direction(pt_widget *widget, pt_ui_direction direction)
```

**Header:** [`pt/widget.h`](../include/pt/widget.h)

Direction properties (since 2.0). UI direction orders row children, resolves
start/end alignment, padding and margins, scrollbar sides and mirrorable
chrome; text direction controls paragraph ordering and glyph shaping. They
are independent, so an LTR editor can sit inside an RTL shell.

UI resolution is the widget's explicit value, then the nearest ancestor with
an explicit value, then the window, then the application, then LTR. Text
resolution is the widget's explicit value, then the nearest ancestor, then
auto. Auto follows UBA P2/P3: the first strong character in a paragraph
selects RTL for R/AL and LTR for L, text inside an isolate is skipped, and an
empty or neutral-only paragraph falls back to the resolved UI direction.

Setters store the explicit value, ignore NULL or an out-of-range enum, and
invalidate layout and repaint on a change. Getters return the stored explicit
value, never the resolved one: an unset widget reports
pt_ui_direction_inherit or pt_text_direction_auto. Both zero values keep the
1.x LTR behaviour. Direction is a presentation property; it never changes
UTF-8 byte offsets, selections or accessibility character offsets. Since 2.0.

**Contract**

- No-op for NULL objects or out-of-range values; no error is returned.

### pt_table_columns_save

```c
char * pt_table_columns_save(const pt_widget *table)
```

**Header:** [`pt/widget.h`](../include/pt/widget.h)

Versioned column-layout persistence. pt_table_columns_save serializes the
current display order plus each column's width, hidden flag and the
multi-column sort state. Titles, alignment and resizability are model
configuration and are not saved. The result is a NUL-terminated ASCII blob
owned by the caller (release with pt_free), or NULL when the table is not a
table, a column width is not finite/positive/representable, or the blob
would exceed PT_TABLE_COLUMN_LAYOUT_MAX. The application decides where to
store it (file, configuration, database); Pt never touches the filesystem
here. The format is:

    PTCOLS 1
    C <count>
    <key> <width> <hidden>        count times, in display order
    S <sort_count>
    <ordinal> <direction>         sort_count times

<key> is '-' for a column without a key, otherwise the key bytes as
lowercase hex (empty keys are matched by position). <width> is the width in
thousandths of a logical pixel (120000 is 120 px) and must be positive;
values below the implementation minimum are clamped on restore. <hidden> is
0 or 1. <ordinal> indexes the column lines above (so sorting follows a
column across reorders) and <direction> is 1 (ascending) or 2 (descending).
A later version may append fields, but the version number changes and older
readers reject it.

pt_table_columns_restore validates the whole blob before touching the table.
It returns false for a NULL table or blob, an oversized blob, an unknown
magic or version, a truncated or malformed line, a non-finite or
non-positive width, an unknown hidden flag, a bad key, more than
PT_TABLE_MAX_COLUMNS columns, more than PT_TABLE_MAX_SORT_COLUMNS sort
entries, a duplicate sort ordinal, a direction other than ascending or
descending, or trailing junk. Column
matching is strict: the saved count must equal the current column count;
each non-empty saved key must match exactly one current column; each empty
saved key is matched by its display position. A missing or duplicate key,
or a mixed set that cannot form a permutation, rejects the blob. On failure
the current layout is untouched (atomic); on success the saved widths,
visibility, order and sort state are applied and the table rebinds. Since 1.2.

**Contract**

- Valid object: `pt_widget_table`. Other widget kinds are ignored.
- Returns NULL for invalid arguments or when no value is available.

## window.h

Windows, clipboard and input handlers.

**Contract**

Threading. UI thread only, including getters.
Ownership. The application owns every window; pt_window_create returns a
borrowed handle that pt_app_destroy releases. A window owns its root widget
tree and its toast handles. pt_window_clipboard_get returns memory owned by
the caller and released with pt_free; every other returned pointer or string
is borrowed.
Errors. pt_window_create returns NULL and sets pt_get_last_error. Setters are
no-ops for NULL windows or invalid theme tokens. pt_window_close is a request,
not a destruction: the close callback may veto, and destruction is deferred
until the current dispatch finishes. Theme getters return the app value when
the window has no override.
Callbacks. Close, resize, key and drag-finished callbacks run on the UI
thread; user_data must stay valid until the callback is replaced or the
window is destroyed. Pointer and text arguments passed to a callback are
valid only during that call.
Popups. A grabbed xdg_popup belongs to the compositor. popup_done dismisses
the overlay instead of falling back to the in-window path. The grab serial is
the window's last pointer serial, or the seat's most recent serial when no
pointer event has landed on the window. Menus, tooltips and select-only
combobox popups inherit this contract (see overlay.h).
Decoration. set_mode is a preference; the compositor's configure is
authoritative. Requested and effective modes are tracked separately.
pt_window_set_decorated controls only whether Pt paints its header.

**Header:** [`pt/window.h`](../include/pt/window.h)

is widget -> nearest explicit ancestor -> this window -> application -> LTR.

values outside pt_ui_direction, and invalidates the window layout and repaint
on a change. pt_ui_direction_inherit is the zero value.

### pt_window_clipboard_set_image_png

```c
bool pt_window_clipboard_set_image_png(pt_window *window, const pt_color *pixels, int width, int height)
```

**Header:** [`pt/window.h`](../include/pt/window.h)

PNG clipboard images (image/png). The setter takes premultiplied 0xAARRGGBB
pixels, row-major with a stride of width, the same layout as
pt_window_paint_pixels, converts them to straight-alpha RGBA and writes a
PNG. Conversion rule: a transparent pixel encodes as RGB 0; otherwise each
component is round(component * 255 / alpha) clamped to 255, and the alpha
byte is unchanged. The setter copies; the caller keeps ownership. It
returns false for NULL, a non-positive size, a size above
pt_clipboard_image_max_dimension, or an encode/transfer failure, and records
the reason in pt_get_last_error().

The getter returns caller-owned premultiplied 0xAARRGGBB pixels (release
with pt_free()) and stores the decoded width and height in the out
parameters, which may be NULL. Decoding reuses the text clipboard transfer
cap (1.5 s, 16 MiB) and rejects dimensions above
pt_clipboard_image_max_dimension, corrupt data and decompression bombs by
returning NULL with the out parameters set to zero and an error recorded;
it never crashes. The decoder accepts 8-bit non-interlaced PNG colour types
0/2/3/4/6; other PNG variants are rejected rather than approximated.
Headless and self-owned selections use the in-process fallback, exactly like
the text clipboard. Setting any clipboard type replaces the previous one, so
a successful image set makes the text getter return NULL. Since 1.2.

**Contract**

- Returns false for an invalid object or when the operation or query does not apply.
