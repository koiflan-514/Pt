## Conventions

**Threading.** Pt is single-threaded. Every function, callback, timer and frame must be driven from the thread that created the application. Do not call the C API from worker threads; marshal work with a timer or an application-owned queue instead.

**Ownership.** Constructors that take a parent append to it and transfer ownership to the parent's subtree. Functions returning handles either return a borrowed pointer owned by a container or allocate an object the caller must destroy; each function entry states which applies. Never free a borrowed pointer. `pt_free` releases buffers that Pt explicitly hands to the caller.

**Callback threading and lifetimes.** Callbacks are invoked synchronously on the UI thread during event dispatch, painting or frame advancement. They may call the API, but must not block. A registered callback and its `user_data` stay valid until the callback is replaced or the owning object is destroyed.

**Error behavior.** Functions that can fail by creation or lookup return NULL, false, zero or a documented enum default. `pt_get_last_error` returns a thread-local message for the most recent failure. Setters are no-ops for NULL objects, mismatched widget kinds and out-of-range indices; they do not report errors through return values. Text is UTF-8; text offsets are byte positions.

**Valid widget kinds.** Functions with a kind-specific prefix operate on the named widget kind and ignore other kinds. Functions prefixed `pt_widget_` work with any widget unless their description narrows the set.

## base.h

Core types, errors and memory.

**Contract**

Threading. Pt is single-threaded. Every function that reads or mutates an
application, window, widget, overlay, accessibility model, drag or gesture
state must run on the UI thread that owns the application, including getters
and queries. The exceptions are the value helpers declared in this header and
a short list of functions that touch only caller-owned data: pt_rgba, pt_rgb,
pt_color_alpha, pt_ease, pt_ease_value, the pt_transition_* functions,
pt_uri_list_count, pt_uri_list_get, pt_free and pt_get_last_error. Those keep
no shared mutable state; pt_get_last_error is thread-local. Callbacks always
run on the UI thread. There is no locking, so an off-thread call to anything
else is undefined behavior even when it only reads.

Ownership. Constructors that take a parent append the new object to it and
transfer ownership to the parent's subtree. A handle returned by a container
or a lookup is borrowed and stays valid until the owning object is destroyed
or the specific function documents a shorter lifetime. Only buffers that Pt
explicitly hands to the caller are caller-owned and released with pt_free;
every other returned pointer is borrowed and must not be freed. Strings
passed to setters are copied unless the declaration says otherwise.

Errors. One error model applies to the whole API. Creation and lookup
functions return NULL, false, zero or a documented sentinel on failure and
set the thread-local message returned by pt_get_last_error. Setters return
void and are no-ops for NULL objects, a mismatched widget kind or an
out-of-range index; they do not report an error. Functions returning bool
return false for an invalid object or an operation that does not apply.
Getters clamp their arguments and return a default instead of failing.
Allocation failure is fatal: Pt prints a diagnostic and aborts rather than
returning a half-initialized object.

Strings and callbacks. Text is UTF-8 and text offsets are byte positions.
A pointer argument passed to a callback is valid only for the duration of
that callback unless the callback typedef says otherwise; copy the data to
keep it. user_data is passed through unchanged and must stay valid until the
callback is replaced or the owning object is destroyed.

## theme.h

Theme tokens and helper functions.

**Contract**

The color and metric enums are append-only ABI: existing numeric values never
change and new roles get fresh numbers. pt_theme_token_count and
pt_theme_metric_count are bounds, not roles.
Colors are 0xRRGGBBAA; metrics are logical pixels. Negative metrics clamp to
zero, and a radius_pill may be large because it is clamped to the shorter side
of each shape. Out-of-range token or metric indices are ignored by setters;
the getters return 0 for them.
The setters and getters live in app.h and window.h and are UI-thread only. A
window resolves app tokens first and then its own overrides at paint time; no
allocation is transferred by this header.

This header declares types only.

## app.h

Application lifecycle, timers and preference.

**Contract**

Threading. UI thread only, including getters. Timers and the accessibility
event callback run on that thread.
Ownership. pt_app_create returns an application owned by the caller until
pt_app_destroy, which destroys its windows, widget trees, overlays and
timers. Timer ids are values, not handles; a fired id is forfeited.
Errors. pt_app_create returns NULL and sets pt_get_last_error when the
compositor connection fails. pt_app_run and pt_app_run_for return -1 only on
a connection failure; timeout and a normal quit return 0.
pt_app_add_timeout returns 0 when the timer could not be queued.
pt_app_set_font_family copies the string. Theme setters clamp as documented
in theme.h; queries return the stored value.
Callbacks. A timer callback is one-shot, runs on the UI thread and may not
block; user_data must stay valid until it fires or the timer is cancelled.

## window.h

Windows, clipboard and input handlers.

**Contract**

Threading. UI thread only, including getters.
Ownership. The application owns every window; pt_window_create returns a
borrowed handle that pt_app_destroy releases. A window owns its root widget
tree and its toast handles. pt_window_clipboard_get returns memory owned by
the caller and released with pt_free; every other returned pointer or string
is borrowed.
Errors. pt_window_create returns NULL and sets pt_get_last_error. Setters are
no-ops for NULL windows or invalid theme tokens. pt_window_close is a request,
not a destruction: the close callback may veto, and destruction is deferred
until the current dispatch finishes. Theme getters return the app value when
the window has no override.
Callbacks. Close, resize, key and drag-finished callbacks run on the UI
thread; user_data must stay valid until the callback is replaced or the
window is destroyed. Pointer and text arguments passed to a callback are
valid only during that call.
Popups. A grabbed xdg_popup belongs to the compositor. popup_done dismisses
the overlay instead of falling back to the in-window path. The grab serial is
the window's last pointer serial, or the seat's most recent serial when no
pointer event has landed on the window. Menus, tooltips and select-only
combobox popups inherit this contract (see overlay.h).

## widget.h

Widgets, containers and data views.

**Contract**

Threading. UI thread only, including getters and accessibility queries.
Ownership. Constructors append the new widget to parent and transfer
ownership to the parent's subtree. A NULL parent returns a detached tree owned
by the caller and released with pt_widget_destroy. Handles returned by
pt_widget_parent, the pt_tree_* lookups, pt_tabs_get_page and
pt_sidebar_get_item are borrowed. Text returned by a getter is borrowed from
the widget and invalidated by the next mutation of that text. List, table and
tree row/cell widgets are materialized and owned by the view: a bind callback
must configure them but never destroy or reparent them.
Errors. Constructors return NULL and set pt_get_last_error. Setters are
no-ops for NULL, a mismatched widget kind or an out-of-range index. Functions
returning bool return false for an invalid object or an operation that does
not apply. Getters clamp and return a default. Selection and checked-state
setters are silent: they never fire on_select, on_change or on_checked,
matching every set_selected in the API.
Callbacks. All callbacks run on the UI thread. user_data must stay valid until
the callback is replaced or the owning widget is destroyed. A text pointer
passed to a callback is valid only for that call unless its typedef says
otherwise. Callbacks may call the API and may destroy their own widget after
returning; they must not block.
Text input. Pt pushes text-input-v3 state when focus enters a text input,
when a keystroke or pointer gesture changes the text or caret, and when a
composition ends: content type, surrounding text, caret rectangle, then
commit. An empty done with no composition in flight is the input method's
acknowledgement and is ignored, because replying to it would ask for another
acknowledgement. The push moments are part of the frozen contract.
Text. Strings are UTF-8 and offsets are byte positions. Selection endpoints
may be given in either order and are clamped. Strings passed to setters and
span arrays are copied.

## overlay.h

Menus, dialogs and toasts.

**Contract**

Threading. UI thread only, including getters and show/dismiss.
Ownership. pt_menu_create and pt_dialog_create return objects owned by the
caller and released with the matching destroy function, independently of the
window that hosts them. pt_window_show_toast returns a window-owned handle
that becomes invalid when the toast is dismissed or the window is destroyed.
Menu labels, shortcuts, dialog text and toast text are copied.
Errors. Creators return NULL and set pt_get_last_error. Setters are no-ops for
NULL. Showing an already open overlay is a no-op; dismiss and close are safe
in any state, and is_open/is_visible report false for NULL.
Callbacks. Menu item, dialog action and on-close callbacks run on the UI
thread after the overlay has closed, so they may open another overlay, mutate
the tree or destroy the handle. user_data must stay valid until the menu or
dialog is destroyed or the callback is replaced.
Surfaces. Dialogs and toasts stay in the parent surface. Menus and tooltips
may use a native xdg_popup, whose grab follows the contract in window.h:
popup_done dismisses the overlay and never falls back to the window path.

## dnd.h

External drag and drop.

**Contract**

Threading. UI thread only. Drop, offer and stream callbacks run on the UI
thread from the event loop.
Ownership. pt_drop_offer_mime, pt_drop_offer_selected_mime and
pt_drop_stream_mime return borrowed strings that stay valid for the callback
that inspected them, or until the stream ends. pt_drop_offer_read returns a
