# 架构

[English](../architecture.md) | 简体中文

## 目标与非目标

Pt 是一个 Wayland 原生 GUI 框架，面向逻辑可以用 C、C++、Python 或 Java
编写的应用程序。它以 Linux 桌面为目标，优先考虑精简的依赖面、可预测的
内存所有权、清晰的文本以及精致的默认外观。

它不是通用 3D 工具包、合成器、Web 运行时，也不是对 X11/Win32/macOS 的
跨平台抽象。在 0.x 系列中，Linux/Wayland 是唯一的底层平台。

## 分层

```
application code (C / C++ / Python / Java)
                  |
             public C ABI
                  |
  widgets -> layout -> damage -> paint -> backing canvas -> wl_shm buffer
   |  |                 |          |
   |  data views /      |      text shape cache
   |  table & tree       overlay stack
   |  text area / icons  |
   |                    |
  input            menus / dialogs / toasts / tooltips
   |
  accessibility model and event stream
   |
 Wayland seat (pointer, keyboard, touch, tablet-v2), xdg-shell,
 fractional-scale, xdg-decoration, data-device, text-input-v3
```

公共 C ABI 扁平且不透明：不暴露任何包含平台句柄的结构体，回调携带
`void *user_data`，颜色是打包整数。这使 ctypes 和 Java Foreign Function &
Memory API 绑定保持小巧。库以 `-fvisibility=hidden` 构建；只有标记为
`pt_api` 的函数会被导出（1.0 中为 412 个，0.10.0 中为 414 个）。内部头文件
位于 `src/`，不会被安装。

## 设计决策

### 保留模式控件

保留树使状态和生命周期明确，并让每种语言绑定都能持有一个不透明句柄。
立即模式 UI 会简化 C 绘制，但会把更多绑定逻辑推过 FFI 边界（每一帧都要
跨越语言边界），对于 Python 和 Java 后端来说，这是错误的权衡。

### 基于 wl_shm 的软件渲染器

默认路径使用 `wl_shm`，避免了 GL 上下文、EGL 供应商耦合以及依赖合成器的
交换链。GUI 工作负载以圆角卡片、文本和平面表面为主；扫描线/覆盖率渲染器
能很好地处理这些内容。只有在状态变化或动画运行时才绘制帧，Wayland 帧回调
负责调节节奏。以后可以在同一画布 API 之下添加 GPU 渲染器；首个版本并不
需要它。

画布在内存中使用预乘 ARGB8888（小端系统上为 0xAARRGGBB），与
`WL_SHM_FORMAT_ARGB8888` 语义一致。公共颜色约定为 0xRRGGBBAA，并在边界处
转换。

### 文本

FreeType 提供带 hinting 的字形光栅化，HarfBuzz 提供字形整形（连字、组合
标记、复杂文字系统、CJK），Fontconfig 解析字体族和回退字体。字形覆盖率按
字体面和字号缓存在一个小型哈希表中。文本按逻辑坐标测量和绘制；物理字号
乘以窗口缩放，因此分数缩放仍然清晰。

直接从覆盖率绘制文本避免了图集纹理，并使渲染器不依赖 GPU API。大型文本
密集型文档以后可能受益于图集；缓存边界属于内部实现。

测量和整形后的文本段按字体缓存。键将 FNV-1a 哈希与完整字节比较相结合，
因此哈希碰撞不会产生错误的字形。每种字体保留一个 256 项的 LRU，上限为
256 KiB 的保留 HarfBuzz 缓冲区，每个文本 8 KiB；重复的标签、滚动帧和局部
重绘会复用整形后的文本段，而不是重新运行 HarfBuzz。该缓存是内部实现，
不提供公共保留契约。

Fontconfig 初始化是主要的冷启动开销。`ensure_library` 在第一次文本操作时
惰性调用 `FcInit`，然后按字体族/字重/像素字号三元组在进程级列表中缓存一个
`pt_font`。FreeType 字体面和 HarfBuzz 字体会在进程的整个生命周期内保留。
这是有意的延迟/内存权衡：第一帧承担字体发现和字形光栅化的成本，后续帧
复用它们。有关测得的 RSS/PSS，参见 [performance.md](../performance.md)。

### 多行编辑

文本区域复用输入框的编辑状态：一个 UTF-8 字节插入符号、一个独立的选择
锚点、32 份快照的撤销，以及相同的剪贴板和输入法路径。布局在
`text_layout.c` 中按控件宽度贪心断开逻辑行，生成带字节范围和统一行高的
视觉行；换行绝不会拆分 UTF-8 序列。绘制只遍历与内部裁剪区域相交的视觉行，
并将选择字节偏移映射回行矩形。

插入符号仍然是字节偏移。垂直移动会把当前插入符号的 x 位置转换为一个目标，
并应用到上方或下方的视觉行，因此穿过短行和长的换行行时不会水平漂移。
Home/End 作用于视觉行边界；Enter 插入 `\n`。滚动是控件内部的，由编辑操作和
`scroll_to_caret` 请求，而不是由绘制请求：绘制从不改变滚动状态，这使损坏
区域遍历保持幂等。内容自适应在布局期间忽略请求的高度，改为报告换行后文本
的高度。输入框保持单行，并支持插入符号水平滚动。

### 缩放

`fractional-scale-v1` 的首选缩放被解释为以 120 为分母的分数。当可用时，缓冲区
按 `ceil(logical * scale)` 分配，使用 `wl_surface.set_buffer_scale(1)` 和
`wp_viewport.set_destination(logical_size)`。没有分数缩放时，改用
`wl_surface.preferred_buffer_scale`（合成器 v6）或保守的整数缩放。缩放在
变化时会重新创建缓冲区。

### 装饰

Pt 协商 `zxdg_toplevel_decoration_v1`。它请求客户端模式，以便默认标题栏具有
一致的外观。如果合成器坚持使用服务端装饰，Pt 会省略自己的标题栏。客户端
标题栏通过 xdg-shell 请求处理移动、调整大小、最大化和关闭。这在 niri 和
基于 wlroots 的桌面等平铺合成器上很重要，因为这些合成器并不总是显示服务端
装饰。

44 px 的逻辑标题栏包含标题、最小化/最大化/关闭控件，以及内容区域之外 6 px
的边缘/角落调整大小区域。这些区域的悬停跟踪和命中测试在指针移动时重新
计算，并从 Xcursor 主题生成调整大小光标。

### 输入、输入法和剪贴板

每个 seat 提供一个指针、键盘和数据设备。指针事件进入窗口，先对标题栏进行
命中测试，然后对控件树进行命中测试；控件接收窗口坐标中的 enter、leave、
down、up 和 drag。滚动容器在其边界内消费滚轮轴事件。光标从光标主题加载并
设置到指针表面；标题栏为八个调整大小方向提供调整大小光标。

打开的覆盖层位于指针和控件树之间。菜单、对话框或工具提示面板首先接受命中
测试；在菜单外单击会关闭它，模态对话框会消费外部单击并捕获焦点，工具提示
是被动的。键盘输入遵循相同的优先级：覆盖层焦点作用域处理 Tab/Shift+Tab 和
方向键，Escape 关闭菜单和对话框，之后焦点恢复到先前获得焦点的控件。

来自 seat 的 `wl_touch` 能力馈入同一个内部指针路径：触摸 down/up/motion/
cancel 变成指针 down/up/motion/cancel，取消会在控件之外的位置释放，因此不会
触发任何操作。因此，点按、拖动和基于拖动的滚动无需更改即可工作。Pt 最多
跟踪十个活动触摸 id；第二个接触点会取消进行中的指针交互，并切换到合成的
双接触捏合/旋转流，除非合成器已经为该 seat 报告捏合手势。每一帧从跟踪的
接触点推导质心、距离和角度，将它们归一化为与合成器手势相同的
`pt_gesture_event` 形状，并在剩余接触点少于两个时结束手势。

`zwp_tablet_manager_v2` 工具提供触控笔输入。在工具的 `frame` 事件之前，会
收集接近、笔尖 down/up、移动、压力、距离、倾斜和旋转，然后以逻辑窗口坐标
中的单个 `pt_stylus_event` 交付。相同事件也会镜像到指针路径，因此控件无需
任何应用代码就能获得悬停和单击语义；触控笔回调是为压感工具提供的追加式
数据流。压力和距离归一化到 `[0, 1]`，倾斜以度为单位，旋转从协议的度转换为
弧度。

`zwp_pointer_gestures_v1` 提供滑动和捏合事件（包括旋转），hold v3 在可用时
提供合成器三指按住。Pt 还从指针按下合成单指长按，只要指针保持在 8 px 的
容差内达可配置延迟（默认 500 ms）；合成器的按住与此延迟无关。所有这些都
归一化为一个 `pt_gesture_event` 流：滑动平移累积在 `dx`/`dy` 中，捏合
`scale` 相对于手势起点，旋转以弧度累积，目标是在手势开始时质心下方的控件。
交互层还会在轴停止后将连续的触摸板轴源转换为惯性滚动，速度根据协议时间戳
和指数摩擦估算。新的轴事件、指针按下、离开或触摸取消会停止动量，滚动在
容器边界处钳制。应用循环将下一个长按截止时间纳入其 poll 超时，因此按住会
按时触发，而不会忙等。

键盘处理使用合成器提供的 xkbcommon 键映射。键符和 UTF-8 文本首先交付给
窗口级按键回调，然后在 Tab/Shift+Tab 遍历之后交付给获得焦点的控件。事件
循环为不替客户端重复按键的合成器实现按键重复：遵循键映射的 `repeat_info`
速率和延迟，回退值为 500 ms/25 Hz。重复使用应用定时器队列，而不是忙等。

当输入框获得焦点时启用 `zwp_text_input_v3`，离开时禁用。启用文本输入并不会
把每个键都交给输入法：输入法未消费的键仍作为 `wl_keyboard` 事件到达，并
根据其 xkb UTF-8 文本插入，而 `commit_string` 携带组合后的文本。协议要求这种
拆分，因为它将普通键盘键入视为文本变更，必须像输入法提交一样反映在周围
文本中。预编辑和提交字符串按 `done` 事件收集，应用到获得焦点的输入框，
插入符号矩形报告回合成器以用于候选窗口。Pt 在三个时刻推送状态，1.0 将其
冻结：焦点进入文本输入时（启用、内容类型、周围文本、插入符号矩形）；每当
按键、指针手势或程序化编辑改变文本、插入符号或选择时（周围文本和插入符号
矩形）；以及组合结束时，无论是通过提交、预编辑应用还是取消（相同的更新，
插入符号放在组合结束的位置）。每次推送都以 `commit` 结束。一个不携带提交
字符串、没有预编辑、也没有删除范围的 `done` 是输入法在确认 Pt 刚刚推送的
状态，因此没有进行中组合的输入框会忽略它而不是回复：回复会推送另一次状态
更新，从而要求另一次确认，而在真实桌面上，双方随后会互相占用——对于获得
焦点的输入框，测得每秒 13,500 轮，每轮都有一次重绘和一个
`selection_changed` 事件。组合过程中到达的空 `done` 仍然是唯一的组合结束
信号，因此它会像以前一样清除预编辑并重绘。同样的三个时刻在
`include/pt/widget.h` 中说明，并由 `test_ime` 固定，因为针对 1.0 编写的输入法
引擎会假定它发送的每个事件都会得到回复。

输入框编辑建模为带插入符号和独立选择锚点的 UTF-8 字节位置。每次编辑之前
都会对锚点和光标进行归一化，因此可以向任一方向进行选择。鼠标按下开始
选择，拖动扩展选择，双击选择一个词（ASCII 字母数字、`_` 以及除表意空格
以外的非 ASCII 码点），三击选择全部。Shift+方向键、Shift+Home/End 和 Ctrl+A
扩展或替换选择；插入文本、Backspace、Delete、剪切和粘贴会替换选择。撤销/
重做最多使用 32 份文本加插入符号/锚点状态的快照；新的编辑会清除重做分支。
输入法预编辑带下划线绘制，在提交之前绝不会进入撤销历史。

剪贴板支持使用 `wl_data_device` 和 `wl_data_source`。传出的文本以
`text/plain;charset=utf-8`、`text/plain` 和 `UTF8_STRING` 提供；传入的选择
数据通过非阻塞管道读取，超时为 1.5 秒，上限为 16 MiB。剪切/复制/粘贴和公共
`pt_window_clipboard_set/get` API 共享此路径。返回的剪贴板字符串由 malloc
分配，并使用 `pt_free` 释放。

外部拖放复用数据设备路径。拖动进入会命中指针下方最深的已注册放置目标；
enter 回调选择是否接受提供的 MIME 类型，motion 和 leave 回调跟踪悬停，drop
使用相同的超时和大小上限读取类文本数据。放置目标由后代继承，
`pt_widget_get_drop_hover` 暴露当前状态。一旦选择被拖动几个像素，输入框就
成为拖动源；`pt_window_begin_drag` 在指针的隐式抓取有效时为自定义控件启动
拖动，提供文本、URI 列表或带 MIME 类型的调用方提供的字节；目标通过
`pt_drop_offer_mime_count`、`pt_drop_offer_mime`、`pt_drop_offer_has_mime` 和
`pt_drop_offer_actions` 检查整个 offer，在 `enter_offer` 中选择一种类型，
并用 `pt_drop_offer_read` 流式读取它。`pt_window_begin_text_drag` 和
`pt_window_begin_uri_drag` 都是较旧的单一类型形式；它们在 0.9 中弃用，并在
1.0 冻结候选版本中被移除，因此 `pt_drag_data` 条目是唯一的来源。RGBA 拖动
缩略图可以通过 `pt_window_set_drag_image` 替换内置缩略图。`pt_uri_list_*`
辅助函数解析容忍 CRLF 的 URI 列表，跳过注释和空行，并将每个 URI 作为新分配
的字符串返回。

### 布局与绘制

布局是对可见子项执行的单次保留模式 flex 过程：内边距、外边距、间隙、
显式/自动尺寸、最小/最大约束、增长权重、交叉轴对齐和六种 justify 模式。
带文本的控件在布局期间通过 FreeType/HarfBuzz 测量，包括换行标签的高度。
滚动容器按完整宽度减去滚动条槽来布局其内容，并在绘制期间裁剪。在 1.0 中
方向是逻辑的：文本按 UTF-8 字节顺序存储和索引，行子项从第一个子项到最后
一个子项放置，`start`/`end` 对齐是物理左/右。HarfBuzz 会猜测它整形的单个
文本段的文字系统和方向，但没有段落重排序或双向偏移映射。[rtl.md](rtl.md)
规定了 1.0 之后的方向模型、UBA 流水线、UI 镜像以及编辑所需的逻辑到视觉
映射。

换行和网格在同一次过程中测量。换行测量每个子项，当下一个子项加上列间隙会
超过内部宽度时开始新的一行；每一行独立对齐，其高度是最高的子项。网格将
内部宽度分成相等的列，遵循每个子项的跨度（钳制到列数），并给每一行最高
单元格的高度。两者默认在交叉轴上拉伸子项，因此标签片等固有宽度的子项会将
`align_self` 设置为 start。容器在任何宽度变化时重新计算，这使窗口调整大小
成为唯一的重排触发因素。

虚拟化列表也是一个带有布局遍历的普通控件，但它的子项是固定池，而不是每个
数据条目一行。布局从 `scroll_y`、行高和视口高度推导可见索引范围，增加一行
过扫描，并通过应用程序回调重新绑定池中的行。范围之外的行被隐藏并复用。
因此布局和绘制成本随视口高度而不是 `row_count` 扩展；应用程序数据本身留在
控件树之外。选择是列表状态，因此回收的行不会丢失选择；键盘导航会将选中的
行滚动到视图中。行是列表拥有的容器，自定义单元格是其中的普通控件树。

表格和树复用相同的池。表格拥有一个表头行加上一个行控件池，每个行控件为
每列持有一个单元格。布局从 `scroll_y` 推导第一个可见行，通过应用程序回调
绑定池中的单元格并隐藏其余部分，因此行和单元格控件随视口扩展。列宽按列
存储在表格状态中，因此它们在行回收和绑定后仍然存在，并且可以通过拖动表头
分隔线来调整大小。列可以在不丢弃宽度、标题或单元格的情况下隐藏；隐藏列会
被布局、绘制、命中测试和无障碍跳过。单击表头会报告完整的优先级排序列表
（最多四列）；Shift+单击会追加一列，表头会为每个已排序列绘制一个尖角符号。
行键回调提供稳定的 `uint64_t` 标识。表格记录选中的键，在行数变化
和刷新后解析它，并通过 AT-SPI 报告行键；行文本回调为键盘键入预选提供数据，
而无需物化屏幕外的行。批量失效只解绑与某个范围相交的行，因此模型编辑不会
重建池。树在控件树之外拥有一个节点列表（文本、父/子、展开标志、深度、用户
数据），并在结构或展开状态变化时将其展平为可见节点数组。其布局随后绑定
相同类型的池化行。选择和键盘导航是数据视图状态，而不是行状态，因此回收
永远不会丢失它们；Home、End 和 Page 键按视口移动，AT-SPI 报告行/列索引、
排序状态、树层级和展开状态。

编辑位于该池内部，而不是旁边。`pt_table_begin_edit` 分离任何打开的编辑器，
创建一个子输入框，其 `editor_owner` 是表格，用单元格文本填充它，并以列标题
命名，然后聚焦并全选它，因此按键、输入法、剪贴板和撤销都通过普通字段使用
的同一输入框路径运行。提交将草稿复制到单元格，触发编辑回调并发出值变更的
AT-SPI 事件；Escape 分离而不写入。树对节点使用相同的形态：
`pt_tree_begin_rename` 用节点文本填充，提交在重命名回调运行之前替换它。
多行选择是表格状态中的字节位集，带有自己的锚点和计数。`pt_table_select`
将集合折叠为主行，而 Shift+单击按下以及在行上或空视口空间中开始的拖动会
通过 `pt_table_select_range` 扩展它。该拖动还会移动一个逻辑橡皮筋框选
矩形，绘制过程将其裁剪到表格的内部区域；超过四像素的垂直阈值后，它变为
行拖动，其最终索引在指针抬起时报告。表头拖动要么在其分隔线处调整列大小，要么在启用
重排序时，从可见表头单元格的中点跟踪放置目标。提交重排序会在相邻列之间
整体交换宽度、标题、对齐、可调整大小和隐藏标志，重新映射排序优先级列表并
重建表头，因此列的几何形状永远不会与其身份分离。

标签页和侧边栏是布局容器，而不是单独的渲染路径。标签条绘制其标题并管理
页面可见性；页面是普通子控件树，裁剪到内容区域。侧边栏布局图标加标签的
条目，在紧凑模式下切换为仅图标轨道，并像列表一样发出选择。21 个内置图标是
24 单位坐标空间中的描边折线，缩放到请求的像素大小并通过画布线例程绘制，
因此导航不需要图像资源。

绘制使用裁剪栈遍历树。在绘制控件之前，`intersects_clip` 会拒绝无法贡献像素
的子树：控件矩形转换到设备空间并扩展 48 个逻辑像素，以计入阴影和焦点环。
滚动容器在绘制子项之前推入其内容裁剪，因此屏幕外的行会被跳过。

绘制由损坏区域驱动。setter、焦点/悬停变化、定时器和文本编辑通过
`pt_widget_damage`、`pt_window_damage_rect` 或 `pt_window_damage_all` 标记
逻辑矩形；窗口将它们合并直到下一帧。强制完整绘制会重置区域，而
`pt_window_paint_damage` 裁剪到并集并仅清除该区域后重绘。Wayland 后端以设备
分辨率保留一个持久后备画布。每个 `wl_shm` 缓冲区记录自上次刷新以来累积的
损坏区域；当选择某个缓冲区时，当前帧及其待处理区域的并集从后备画布复制，
其他缓冲区累积当前帧以供以后复用。表面版本 4+ 会接收该像素区域的
`wl_surface.damage_buffer`；较旧的表面回退到完整的 `wl_surface.damage`。
没有损坏区域的帧不会附加和提交任何内容，因此空闲窗口和插入符号定时器不会
产生空交换。

标题栏、卡片、按钮、输入框、切换开关、复选框、单选框、滑块、进度条、旋转
指示器、分段控件、标签页、侧边栏、表格、树、滚动条和焦点环使用抗锯齿圆角
矩形 SDF 覆盖率、渐变、边框和柔和阴影。图标共享相同的颜色和损坏区域路径；
表头和树行复用列表行绘制原语。所有颜色来自 38 个语义角色（表面层级、容器
和凹陷变体、边框和轮廓、文本和禁用文本、强调色层级、控件和轨道表面、带
柔和变体的危险/成功/警告、焦点、选择、遮罩、骨架对和阴影），几何来自 10 个
度量（圆角半径、焦点宽度和偏移、悬浮高度、标签片和控件高度）。查找先遍历
按窗口的覆盖表，然后是应用主题，最后是调色板默认值，因此深色和浅色调色板以及按
窗口重设样式共享一条绘制路径；固定自己背景或前景的控件仍会绕过该表。切换
旋钮、复选框选中标记、旋转指示器阶段和不确定进度是基于时间的混合，仅在
移动时保持帧调度。程序化状态 setter 会将动画阶段直接跳到终值，因此刚构建
的 UI 会以最终状态绘制。

### 动效

动效表示为随时间变化的值，而不是动画运行时。`pt_ease` 通过固定曲线集映射
归一化时间；`pt_transition` 存储值、起点、目标、已用时间和活动标志，不进行
分配或注册。活动期间重新设定目标会从当前值重新开始，因此中断是连续的。
应用程序通过自己的定时器推进过渡并请求重绘；框架控件对悬停、选中和展开/
折叠使用相同的数学。

减少动态效果是应用状态。启用时，内置控件动画会直接跳到终点而不是插值；内部
控件直接读取应用标志，而不是将其装饰包装在公共过渡中。`PT_REDUCED_MOTION`
提供初始值。这使该偏好可以通过公共 API 观察，而无需隐藏的全局变量或第二个
动画调度器。

### 覆盖层

菜单、对话框、浮层通知和工具提示共享一个覆盖层模型。对话框和浮层通知在
所属窗口内合成；菜单和工具提示在后端支持时使用原生 `xdg_popup` 表面，否则
回退到窗口内路径。`pt_window_set_popup_policy` 显式选择 `auto`、`native` 或
`window`。每个覆盖层由 `pt_overlay` 记录描述：种类、打开状态、被动/模态
标志、面板控件、逻辑矩形、焦点作用域、定时器和排队操作列表。窗口保留一个
z 序列表（`toasts < menus < dialogs < tooltips`），因此绘制、命中测试、焦点
遍历和损坏区域都遵循相同的顺序。面板是普通控件树：菜单项是带 `menu_item`
角色和可选快捷键字符串的幽灵按钮，对话框操作是按钮。这复用了现有的布局、
绘制、键盘和动画路径，而不是第二套控件系统。

菜单项和对话框操作附加一个小的操作记录。单击时，先移除覆盖层，然后运行
回调，因此回调可以安全地打开另一个覆盖层、修改树或销毁句柄。移除的面板和
操作记录在绘制后的延迟点收集。打开菜单会关闭其他菜单和活动工具提示。工具
提示在悬停时启动按控件的延迟定时器，并且对焦点是被动的。浮层通知堆叠在
右下角，暴露 alert 角色，并通过窗口拥有的定时器过期。

对话框绘制模态遮罩，将其卡片居中，在操作之间捕获 Tab/Shift+Tab，按 Escape
关闭并恢复先前的焦点。对话框和浮层通知面板留在窗口内，因此可以在其边界处
裁剪；菜单和工具提示可以通过原生弹出层跨越窗口边缘。

原生弹出层拥有一个子 `xdg_surface`/`xdg_popup`、一个用于分数缩放的可选
`wp_viewport` 以及自己的三缓冲 `wl_shm` 缓冲区。定位器锚定在右下角，向合成器
请求滑动和翻转约束调整，并可以在锚点移动时重新定位。菜单在打开时抓取 seat；
工具提示设置空的输入区域，以便单击穿透。抓取序列号是窗口的最后一个指针
序列号，或者在该窗口上尚无指针事件落地时是 seat 最近的序列号，因此从按键
处理程序打开的菜单会使用 seat 最后看到的任何序列号进行抓取。合成器的
`popup_done` 会关闭覆盖层，局部点转换使两条路径上的命中测试和绘制保持一致。

### 无障碍

控件根据其种类和内容推导无障碍模型：角色、可访问名称、描述、状态位
（`visible`、`enabled`、`focusable`、`focused`、`checked`、`selected`、
`editable`、`busy`、`expanded`、`expandable`、`modal`、`selectable`、
`multi_selectable`）、带插入符号/选择偏移的文本以及归一化的数值。应用程序
可以通过公共 API 覆盖角色、名称和描述。输入框暴露 UTF-8 字节偏移；文本区域
增加 text-frame 角色和相同的偏移；密码输入框隐藏其文本，但保留插入符号和
选择的形状。列表暴露 list 和 list-item 角色、选中的行和可聚焦的行。表格
报告 table、row 和 cell 角色，以及选中行、行键、从 1 开始的行列索引和带方向
的按优先级排序的排序列；树报告 tree 和 tree-item 角色、从 1 开始的层级、
集合中的位置、集合大小和展开状态；标签页和侧边栏暴露其导航角色和活动项；
图标使用 icon 角色。组合框报告 combo-box 和 `expandable`，并在其弹出层打开
时附加 `expanded`，弹出层本身是 list item 的列表框。标签和按钮报告零偏移。
对话框面板和菜单项会自动获得其 dialog/menu 角色。

选择报告为一个集合，而不是单一行。列表、表格、树或侧边栏的每个已启用行都
带有 `selectable`，模型已选中的行在此基础上带有 `selected`，因此阅读器可以
将未选中的行播报为用户仍可做出的选择。三个数据视图还带有
`multi_selectable`，因为它们的选择可以包含多行；侧边栏和标签条一次只提供
一个选择，因此有意不带有该状态。树分支带有 `expandable`，打开时带有
`expanded`；叶子两者都不带。禁用视图或行会从它下面的行中移除 `selectable`，
同时保留集合本身，因此 `selected` 保持开启，容器继续说明它是什么。

应用级回调接收同步的焦点、状态、文本、选择、值、名称和结构事件，并带有
发起事件的窗口和控件。该模型不依赖 D-Bus 或 AT-SPI，因此仍可用于无头测试
和服务器工具。

`pt_app_enable_a11y` 启动一个可选桥接层，通过 D-Bus 将控件树镜像到 AT-SPI2
注册表。Pt 为每个控件暴露一个派生的可访问对象，通过
`org.a11y.atspi.Socket.Embed` 注册根，并提供 `Accessible`、`Application`、
`Component`（包括绝对范围）、`Action`、`Text`、`EditableText`、`Value`，以及
数据视图上的 `Table`、`TableCell` 和 `Selection`。选择一侧遍历真实行集合：
`GetSelectedChild` 接受其中的索引，`DeselectSelectedChild` 丢弃一行，
`SelectAll` 选择整个模型，`Table.GetSelectedRows` 和
`NSelectedRows`/`NSelectedChildren` 计数报告每个选中的行。状态位映射到其
AT-SPI 名称，`selectable` 映射到 `STATE_SELECTABLE`，`multi_selectable` 映射到
`STATE_MULTISELECTABLE`；展开状态对中表示折叠的那一半会明确写出，因此
一个可以打开但当前关闭的分支会以 `STATE_COLLAPSED` 到达。行上的
`STATE_SELECTABLE` 含义与模型中相同：未选中的行仍然是一个选择。`SelectionChanged` 事件之后是视图
视为其插入符号的行上的 `selected` 状态事件，该行是手势刚刚移动到的行，而
不是集合中最低的行。焦点、状态、文本、选择、值、名称和结构变化会发出
AT-SPI 事件。仅当 `dbus-1` 可用时才编译桥接层。当构建或会话没有无障碍总线
时，`pt_app_enable_a11y` 返回 false，`pt_app_get_a11y_status` 报告
`pt_a11y_status_unavailable`；进程内模型和 Pt 控件继续工作。禁用桥接层不会
影响进程内无障碍模型。

### 事件循环与定时器

`pt_app_run` 和 `pt_app_run_for` 使用感知 Wayland 的阻塞循环：
`wl_display_dispatch_pending`、`wl_display_flush`、`wl_display_prepare_read`、
在显示 fd 和可选 AT-SPI D-Bus fd 上执行 `poll`，然后
`wl_display_read_events`。只有在绘制后窗口变脏或正在动画时才请求帧回调。
空闲时 poll 超时为 250 ms，窗口需要帧时为 16 ms，并缩短到下一个定时器或
交互截止时间（例如待处理的长按）。无头模式对空描述符集使用普通 `poll`，
因此测试会执行相同的定时器和清理逻辑。

定时器是一次性的，由应用拥有，以 64 位 id 标识，并在销毁时取消。关闭请求
由关闭回调检查；接受的关闭会排队，并在循环中的安全点释放，从而防止控件或
窗口回调导致释放后使用。最后一个被接受的关闭会退出循环，除非设置了
`pt_app_set_quit_on_last_window_close(app, false)`。

### 绑定

扁平 ABI 在四个地方被封装：

- C++23：仅头文件的非拥有句柄，加上一个拥有原生图（RAII）的仅可移动
  `pt::app`，提供流畅的 setter 和工厂函数。
- Python 3.10+：一个 ctypes 模块。模块级注册表保留窗口包装器和回调
  trampoline；`user_data` 保持为 `NULL`。行键 trampoline 返回 `uint64_t`，
  行文本 trampoline 在查找期间保留借用的 Python 编码缓冲区。
- Java 22+：一个使用 `Linker.downcallHandle` 和 `upcallStub` 的 FFM 类。处理
  程序接口是显式的，每次注册都接受一个 `Arena`，字符串在每次调用期间于
  受限 arena 中按 UTF-8 分配。行文本使用由 arena 拥有的持久 256 字节 upcall
  缓冲区。
- C：ABI 本身。

没有绑定接触内部结构体或复制布局/绘制逻辑。三个绑定都封装了全部 412 个
公共函数，审计作为 `make check` 的一部分强制检查这种一致性。参见
[bindings.md](bindings.md) 和 [api-reference.md](../api-reference.md)。

### 测试策略

核心、画布、字体、布局、控件和窗口测试是带有小型断言框架的无头可执行文件。
它们在需要时使用内部头文件来验证布局几何、像素和事件语义。窗口套件覆盖
客户端装饰命中区域、光标、分数绘制缩放、调整大小钳制、动画和滚动绘制。
Wayland 套件映射一个真实窗口，演练剪贴板文本并检查 configure 是否产生了
有效的缓冲区缩放；没有可用合成器时，它会跳过并输出一条消息。

时为 236 项检查，否则为 11 项）。实时 Wayland 冒烟测试不属于 `make check`：

取消选择以及 `SELECTABLE`、`MULTISELECTABLE` 和 `COLLAPSED` 状态位。
C++/Python/Java 测试演练相应的绑定表面。渲染器和字体测试还会将 PNG 写入
`build/tests/` 以供手动检查；它们不是黄金文件比较，因为字体光栅化会因字体
包和 FreeType 版本而合理变化。`test_visuals` 改为将单个进程与自身比较，
因此它能捕获绘制流水线中的不确定性，而不会将像素固定到某台机器的字体栈上。

### 线程

Pt 没有内部锁。创建应用的 UI 线程是唯一可以接触应用、窗口、控件、覆盖层、
无障碍模型、拖动、手势或主题状态的线程。这包括 getter：与布局或绘制竞争的
读取与写入是相同的数据竞争，因此“只读”并不意味着“线程安全”。回调和定时器
在该线程上运行，回调可以调用 API。

| 入口点类别 | 线程 | 说明 |
| --- | --- | --- |
| 应用生命周期、窗口、控件、覆盖层、主题 get/set | UI 线程 | getter 也不是线程安全的 |
| 变更、构造函数、销毁、焦点、显示/隐藏 | UI 线程 | 对 NULL、错误类型或错误索引，setter 为空操作 |
| 无障碍模型和事件回调 | UI 线程 | 事件同步交付 |
| 拖放、手势和触控笔状态 | UI 线程 | 回调指针在调用期间借用 |
| 框架回调和 `pt_app_add_timeout` 定时器 | UI 线程 | 不得阻塞；user_data 在被替换前保持有效 |
| `pt_ease`、`pt_ease_value`、`pt_transition_*` | 任意线程 | 仅操作调用方拥有的存储 |
| `pt_rgba`、`pt_rgb`、`pt_color_alpha` | 任意线程 | 纯值辅助函数 |
| `pt_uri_list_count`、`pt_uri_list_get` | 任意线程 | 解析调用方拥有的输入；get 会分配并通过线程局部错误报告 |
| `pt_free` | 任意线程 | 普通的 `free` |
| `pt_get_last_error` | 调用线程 | 线程局部缓冲区，在该线程下一次 Pt 调用前有效 |

1.0 中没有 `pt_app_invoke`。跨线程工作属于由 UI 线程定时器排空的应用程序
拥有的队列；从工作线程使用 Pt 调用 UI 是未定义行为。C++、Python 和 Java
绑定继承相同的规则：在 UI 线程上运行的回调可以调用任何绑定，工作线程则
不可以。

### 内存与错误

对象有明确的拥有者：应用拥有窗口；窗口拥有其控件树和浮层通知句柄；菜单和
对话框由调用方通过 `pt_menu_create`/`pt_dialog_create` 分配，并使用匹配的
destroy 函数释放，独立于承载它们的窗口。覆盖层面板是窗口拥有的控件树，在
关闭后收集。列表拥有其回收的行控件；绑定回调配置行，但不得销毁它们。setter
复制字符串。唯一的全局是线程局部的最后错误字符串和不可变版本数据。分配失败
会带诊断中止，而不是让树处于半有效状态；来自外部系统的错误通过
`pt_get_last_error` 报告。

## 依赖

| 依赖 | 作用 | 必需 |
| --- | --- | --- |
| wayland-client, wayland-cursor | 传输、光标 | 是 |
| xkbcommon | 键盘解码 | 是 |
| fontconfig, freetype2 | 字体查找与光栅化 | 是 |
| harfbuzz | 字形整形 | 是 |
| zlib | PNG 快照压缩 | 是 |
| wayland-protocols / wayland-scanner | 生成的协议代码；XML 已内置 | 仅构建时 |
| libm | 几何 | 是 |

构建 C 库不需要 GL、GTK、Qt、GLib、X11、Rust 或 C++ 工具链。`pt.pc` 将
Wayland/字体/zlib 模块保留在 `Requires.private` 中；公共头文件不暴露任何
依赖类型，因此共享库使用者只需要 `-lpt`（静态链接时还需 libm）。
